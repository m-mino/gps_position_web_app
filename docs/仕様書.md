# GPS位置情報WEBアプリ 仕様書

## 1. 概要

GPS端末（Androidアプリ）から送信される位置情報を収集し、Webブラウザ上の地図で現在地および移動履歴を把握するアプリケーションである。

本リポジトリの責務は次のとおり。

| 実装する | 実装しない |
|----------|------------|
| Webログイン・地図画面 | Androidネイティブアプリ本体（自作） |
| 位置受信REST API / OwnTracks互換API | 端末側のGPS取得ロジックそのもの |
| DB・本仕様書 | |

Androidからのバックグラウンド送信は、自作アプリの代わりに **OwnTracks（HTTPモード）** などの既存アプリを利用できる。本システムはAPIの提供側である。

## 2. 用語

| 用語 | 意味 |
|------|------|
| ユーザー | `users` テーブルの1レコード。Web閲覧とAndroid送信で共通 |
| 位置情報 | 緯度・経度・精度・計測時刻を持つ1レコード（`positions`） |
| 現在地 | あるユーザーについて `recorded_at` が最新の位置情報 |
| 移動履歴 | 指定期間内の位置情報の時系列 |

## 3. アクター

| アクター | 説明 |
|----------|------|
| Web閲覧者 | ブラウザでログインし、全ユーザーの現在地・履歴を地図で閲覧する |
| Android送信者 | OwnTracks等、または別アプリがAPIで位置を送信する |

## 4. 機能一覧

1. Webログイン / ログアウト
2. 地図上に全ユーザーの現在地をリアルタイム表示（Laravel Reverb）
3. ユーザー選択・日付指定による移動履歴（ポリライン・方向・滞在）表示
4. APIログイン / ログアウト（Sanctumトークン）
5. APIによる位置情報登録
6. OwnTracks HTTPモードによる位置受信（バックグラウンド送信向け）
7. APIによる最新位置・履歴取得

## 5. 画面仕様

### 5.1 ログイン画面

- メールアドレス・パスワードで認証（Laravel Breeze）
- 成功後、地図画面へ遷移

### 5.2 地図画面（要ログイン）

- Leaflet + OpenStreetMap で地図を描画
- 全ユーザーの現在地をマーカー表示（ユーザー名ラベル）
- `POST /api/positions` および OwnTracks 受信時に `PositionReceived` をブロードキャストし、地図が WebSocket（Laravel Reverb）で即時更新
- Reverb 未接続時の保険として最新位置APIを約30秒間隔でポーリング
- 「自分の現在地を共有」でブラウザの位置情報を取得し、赤マーカーで表示。同時に `POST /api/positions` へ送信（他ユーザーからも閲覧可能）
- 移動履歴はユーザー選択と **開始日・終了日** で期間指定して表示
- 履歴表示時、同一地点付近に一定時間以上いた箇所を **滞在** として地図上に表示（時間ラベル付き）
- ログアウト導線を持つ

## 6. API契約

ベースURL例: `http://localhost:8080`（本番はデプロイ先ドメイン）

共通:

- 成功時: HTTP 2xx + JSON
- バリデーションエラー: HTTP 422 + `{ "message": "...", "errors": { ... } }`
- 未認証: HTTP 401

### 6.1 POST `/api/login`

認証: なし

リクエスト:

```json
{
  "email": "user@example.com",
  "password": "password",
  "device_name": "android-pixel-7"
}
```

| フィールド | 必須 | 説明 |
|------------|------|------|
| email | ○ | 登録済みメール |
| password | ○ | パスワード |
| device_name | ○ | トークン識別名（端末名など） |

レスポンス 200:

```json
{
  "token": "1|xxxxxxxx",
  "user": {
    "id": 1,
    "name": "山田",
    "email": "user@example.com"
  }
}
```

以降の保護APIでは `Authorization: Bearer {token}` を付与する。

### 6.2 POST `/api/logout`

認証: Bearer

レスポンス 200:

```json
{
  "message": "Logged out"
}
```

現在のアクセストークンを無効化する。

### 6.3 POST `/api/positions`

認証: Bearer

リクエスト:

```json
{
  "latitude": 35.681236,
  "longitude": 139.767125,
  "accuracy": 12.5,
  "recorded_at": "2026-07-16T12:00:00+09:00"
}
```

| フィールド | 必須 | 説明 |
|------------|------|------|
| latitude | ○ | 緯度（-90〜90） |
| longitude | ○ | 経度（-180〜180） |
| accuracy | × | 精度メートル |
| recorded_at | ○ | 端末側計測時刻（ISO 8601） |

`user_id` はトークンのユーザーから決定する（クライアント指定不可）。

レスポンス 201:

```json
{
  "data": {
    "id": 10,
    "user_id": 1,
    "latitude": 35.681236,
    "longitude": 139.767125,
    "accuracy": 12.5,
    "recorded_at": "2026-07-16T03:00:00.000000Z"
  }
}
```

### 6.4 GET `/api/positions/latest`

認証: Webセッション または Bearer

全ユーザーの最新位置を返す。

レスポンス 200:

```json
{
  "data": [
    {
      "user_id": 1,
      "user_name": "山田",
      "latitude": 35.681236,
      "longitude": 139.767125,
      "accuracy": 12.5,
      "recorded_at": "2026-07-16T03:00:00.000000Z"
    }
  ]
}
```

### 6.5 GET `/api/positions`

認証: Webセッション または Bearer

クエリ:

| パラメータ | 必須 | 説明 |
|------------|------|------|
| user_id | ○ | 対象ユーザーID |
| from | × | 開始日（`YYYY-MM-DD`。省略時: 現在−24時間） |
| to | × | 終了日（`YYYY-MM-DD`。省略時: 現在） |

`from` / `to` はアプリタイムゾーンの 00:00:00〜23:59:59 として解釈する。

レスポンス 200:

```json
{
  "data": [
    {
      "id": 1,
      "user_id": 1,
      "latitude": 35.681236,
      "longitude": 139.767125,
      "accuracy": 12.5,
      "recorded_at": "2026-07-16T02:00:00.000000Z"
    }
  ],
  "stays": [
    {
      "latitude": 35.68124,
      "longitude": 139.76713,
      "started_at": "2026-07-16T01:00:00.000000Z",
      "ended_at": "2026-07-16T02:00:00.000000Z",
      "duration_seconds": 3600
    }
  ],
  "meta": {
    "from": "2026-07-16T00:00:00+09:00",
    "to": "2026-07-16T23:59:59+09:00"
  }
}
```

`data` は `recorded_at` 昇順。`stays` は半径約50m以内に5分以上滞在した箇所。

### 6.6 POST `/api/owntracks`

認証: HTTP Basic（email / password）または Bearer

OwnTracks（Android）HTTPモード向け。バックグラウンド位置送信に利用する。

リクエスト例:

```json
{
  "_type": "location",
  "lat": 34.6805,
  "lon": 134.9072,
  "acc": 12,
  "tst": 1720000000
}
```

| フィールド | 必須 | 説明 |
|------------|------|------|
| _type | ○ | `location` のみ処理 |
| lat | ○ | 緯度 |
| lon | ○ | 経度 |
| tst | ○ | Unix時刻（秒） |
| acc | × | 精度(m) |

レスポンス 200: `[]`（OwnTracks仕様）

## 7. DB設計

### 7.1 `users`

Laravel標準（id, name, email, password, remember_token, timestamps）。

### 7.2 `positions`

| カラム | 型 | 説明 |
|--------|-----|------|
| id | bigint PK | |
| user_id | FK → users | 誰の位置か |
| latitude | decimal(10,7) | 緯度 |
| longitude | decimal(10,7) | 経度 |
| accuracy | float nullable | 精度(m) |
| recorded_at | datetime | 端末側計測時刻 |
| created_at / updated_at | | |

インデックス: `(user_id, recorded_at)`, `(recorded_at)`

現在地専用テーブルは持たない。最新位置はクエリで集約する。

### 7.3 `personal_access_tokens`

Laravel Sanctum 標準。

## 8. 非機能

| 項目 | 方針 |
|------|------|
| 地図更新 | ローカルは Laravel Reverb で受信即時更新。未接続時は約30秒ポーリング |
| 閲覧権限 | ログイン済みWebユーザーは全端末の位置を閲覧可 |
| 本番環境 | さくらインターネット レンタルサーバー |
| WebSocket | ローカル Docker では Reverb を使用。共有レンタルでは常駐不可のためポーリングにフォールバック |
| キュー | `database` ドライバ。必要時はさくら cron で `schedule:run` |
| ローカル開発 | Docker Compose（本リポジトリ付属。`reverb` サービス含む） |
