# GPS位置情報WEBアプリ 仕様書

## 1. 概要

GPS端末（Androidアプリ）から送信される位置情報を収集し、Webブラウザ上の地図で現在地および移動履歴を把握するアプリケーションである。

本リポジトリの責務は次のとおり。

| 実装する | 実装しない |
|----------|------------|
| Webログイン・地図画面 | Androidネイティブアプリ本体（自作） |
| 位置受信REST API / OwnTracks互換API | 端末側のGPS取得ロジックそのもの |
| D1・本仕様書 | |

Androidからのバックグラウンド送信は、自作アプリの代わりに **OwnTracks（HTTPモード）** などの既存アプリを利用できる。本システムはAPIの提供側である。

## 2. 技術スタック

| 層 | 技術 |
|----|------|
| Compute | Cloudflare Workers |
| Framework | Hono |
| Database | Cloudflare D1 (SQLite) |
| Web認証（本番） | Cloudflare Access (Zero Trust) |
| Web認証（ローカル） | Cookie セッション |
| 端末認証 | Bearer APIトークン / HTTP Basic |
| 地図 | Leaflet + OpenStreetMap |

## 3. 用語

| 用語 | 意味 |
|------|------|
| ユーザー | `users` テーブルの1レコード。Web閲覧とAndroid送信で共通 |
| 位置情報 | 緯度・経度・精度・計測時刻を持つ1レコード（`positions`） |
| 現在地 | あるユーザーについて `recorded_at` が最新の位置情報 |
| 移動履歴 | 指定期間内の位置情報の時系列 |

## 4. アクター

| アクター | 説明 |
|----------|------|
| Web閲覧者 | ブラウザでログインし、全ユーザーの現在地・履歴を地図で閲覧する |
| Android送信者 | OwnTracks等、または別アプリがAPIで位置を送信する |

## 5. 機能一覧

1. Webログイン / ログアウト（session モード）または Cloudflare Access（access モード）
2. 地図上に全ユーザーの現在地を表示（30秒ポーリング）
3. ユーザー選択・日付指定による移動履歴（ポリライン・方向・滞在）表示
4. APIログイン / ログアウト（APIトークン）
5. APIによる位置情報登録
6. OwnTracks HTTPモードによる位置受信
7. APIによる最新位置・履歴取得

## 6. 画面仕様

### 6.1 ログイン画面（AUTH_MODE=session）

- メールアドレス・パスワードで認証
- 成功後、地図画面へ遷移

### 6.2 地図画面（要ログイン）

- Leaflet + OpenStreetMap で地図を描画
- 全ユーザーの現在地をマーカー表示（ユーザー名ラベル）
- 最新位置APIを約30秒間隔でポーリング
- 「自分の現在地を共有」でブラウザの位置情報を取得し、赤マーカーで表示。同時に `POST /api/positions` へ送信
- 移動履歴はユーザー選択と **開始日・終了日** で期間指定して表示
- 履歴表示時、同一地点付近に一定時間以上いた箇所を **滞在** として地図上に表示（時間ラベル付き）

## 7. API契約

ベースURL例: `http://localhost:8787`（本番は Workers ドメイン）

共通:

- 成功時: HTTP 2xx + JSON
- バリデーションエラー: HTTP 422 + `{ "message": "...", "errors": { ... } }`
- 未認証: HTTP 401

### 7.1 POST `/api/login`

認証: なし

リクエスト:

```json
{
  "email": "user@example.com",
  "password": "password",
  "device_name": "android-pixel-7"
}
```

レスポンス 200:

```json
{
  "token": "1|xxxxxxxx",
  "user": {
    "id": 1,
    "name": "山田",
    "email": "user@example.com"
  }
}
```

### 7.2 POST `/api/logout`

認証: Bearer

レスポンス 200: `{ "message": "Logged out" }`

### 7.3 POST `/api/positions`

認証: Bearer / Session / Access

リクエスト:

```json
{
  "latitude": 35.681236,
  "longitude": 139.767125,
  "accuracy": 12.5,
  "recorded_at": "2026-08-11T00:00:00.000Z"
}
```

レスポンス 201: `{ "data": { ...position } }`

### 7.4 GET `/api/positions/latest`

認証: Bearer / Session / Access

レスポンス 200:

```json
{
  "data": [
    {
      "user_id": 1,
      "user_name": "Test User",
      "latitude": 35.681236,
      "longitude": 139.767125,
      "accuracy": 12,
      "recorded_at": "2026-08-11T04:00:00.000Z"
    }
  ]
}
```

### 7.5 GET `/api/positions`

認証: Bearer / Session / Access

クエリ:

| パラメータ | 必須 | 説明 |
|------------|------|------|
| user_id | ○ | 対象ユーザーID |
| from | - | 開始日 `YYYY-MM-DD`（Asia/Tokyo の日界）省略時は24時間前 |
| to | - | 終了日 `YYYY-MM-DD` 省略時は現在 |

レスポンス 200: `{ "data": [...], "stays": [...], "meta": { "from", "to" } }`

### 7.6 POST `/api/owntracks`

認証: Basic (email:password) または Bearer

OwnTracks location ペイロードを受信し、成功時は常に `[]` を返す。

## 8. 滞在検出

- 連続する位置が **半径 50m 以内**
- かつ継続時間が **300秒（5分）以上**
- 代表座標はクラスタ平均（小数7桁）

## 9. データモデル（D1）

### users

`id`, `name`, `email` (unique), `password_hash` (nullable for Access-only users), timestamps

### positions

`id`, `user_id`, `latitude`, `longitude`, `accuracy`, `recorded_at`, timestamps  
Index: `(user_id, recorded_at)`, `(recorded_at)`

### api_tokens

端末向け Bearer トークン（ハッシュ保存）

### sessions

ローカル session モード用 Cookie セッション

## 10. Cloudflare Access 運用

1. Zero Trust で Self-hosted アプリを作成し Workers URL を保護
2. Application Audience (AUD) を控える
3. `AUTH_MODE=access`, `CF_ACCESS_TEAM_NAME`, `CF_ACCESS_AUD` を設定
4. `/api/login` と `/api/owntracks` は Access Policy で Bypass（Service Auth でも可）
5. Access ログイン成功後、JWT の email で D1 ユーザーを自動 upsert
